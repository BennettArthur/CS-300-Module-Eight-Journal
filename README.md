# CS 300 Portfolio Reflection

 What was the problem you were solving in the projects for this course?

The main problem I was solving was creating a program for ABC University that could efficiently store, organize, and retrieve course information. The program needed to load course data from a file, display a sorted list of courses, and allow advisors to search for a specific course and view its prerequisites. The goal was to determine which data structure would best support these requirements while maintaining good performance.

How did you approach the problem? Consider why data structures are important to understand.

I approached the problem by analyzing multiple data structures, including vectors, hash tables, and binary search trees. I developed pseudocode for each structure and compared their runtime performance and memory usage. Understanding data structures is important because they directly affect how efficiently data can be stored, accessed, and manipulated. Choosing the correct data structure can significantly improve a program's performance and scalability.

How did you overcome any roadblocks you encountered while going through the activities or project?

One challenge was understanding the differences between the performance characteristics of each data structure. I overcame this by reviewing course materials, practicing with pseudocode, and analyzing the Big O runtime of common operations such as insertion, searching, and sorting. Breaking the project into smaller steps made the requirements easier to manage and implement.

 How has your work on this project expanded your approach to designing software and developing programs?

This project helped me understand the importance of planning before coding. Creating pseudocode and analyzing different approaches allowed me to evaluate solutions before implementation. I learned that software design involves selecting appropriate data structures and algorithms based on program requirements rather than simply making the program work.

 has your work on this project evolved the way you write programs that are maintainable, readable, and adaptable?

This project reinforced the importance of writing organized and modular code. By separating functionality into logical components and carefully selecting data structures, programs become easier to read, maintain, and modify. I now place greater emphasis on code organization, documentation, and designing solutions that can be expanded in the future without requiring major changes.
